# 公式仕様メモ(Phase61)

公式チュートリアルセミナー(2026年、SIGNATE/三菱総合研究所)で運営が口頭で確認した
内容をまとめる。**このセミナーでの運営発言も一次資料として扱う**(詳細は
`docs/submission_policy.md` §4 Phase61追記を参照)。文書化された規約と矛盾しない限り、
ここに記載の値は今後のローカル評価・実装判断の前提として使ってよい。

## 1. 前提: 禁止事項(最優先で確認)

セミナー 44:35 付近で運営が明言:

> 「フィードバック結果から、評価基盤で実装されている評価関数の中に設定されている
>   パラメーターとか、手荷物の具体的な内容とかを解析したりするのは基本的にNGなので
>   やめていただきたい」

**この一文がこのドキュメント全体の使い方を規定する。** 以下に列挙する値は、
運営が**自ら公開した**確定値・確定仕様であり、これらを使うこと自体は問題ない。
一方で、ここに載っていない値(足切りの具体的閾値、揺らしテストの正確な振幅、
その他非公開パラメーター)を、**本番のスコアから逆算して特定しようとする行為は
今後一切行わない。** 実施した/検討した詳細は `results/phase61_report.md` を参照。

## 2. 公式が確定した値

| 項目 | 値 | 備考 |
|---|---|---|
| 内包判定のマージン | **5mm** | 荷物を若干浮かせる形で判定 |
| 搬入経路 | 目標高さ **+8cm** の位置から、**Y軸→X軸のL字型** | 単純な直線ではない |
| 経路干渉の余裕 | 棚等との間に **1.5cm以上** | |
| 崩れ判定 | **30cm以上の変位** または **45°以上の回転** | いずれか一方で崩れ扱い |
| タイムアウト | optimize **3分** / policy **8秒** | |
| 揺らしテスト | 最大 **1〜3G程度**(9.8〜29.4 m/s²)を突発的に、単純な縦横ではなく複雑な動き | 正確な波形・振幅は非公開 |
| 足切り | 積み付けられた手荷物の数が一定数以上にならないと、充填率(fill)以外は0点 | **閾値そのものは非公開** |
| 積み直し | 一度積んだ荷物は動かせない | |
| 優先手荷物用コンテナ | 2台のうち**片方のみ**、または**どちらも非優先** | 両方優先の組み合わせはない |
| lookahead | 課題Bは5とは限らず複数の値、課題Cは1 | |
| コンテナあたりの個数目安 | 約40個 | |
| 底面のめり込み判定 | 緩めに設定(不当に弾かれないよう配慮済み) | |
| 扉付近での転倒 | 倒れて外に出た荷物は充填率の対象外 | |

## 3. このメモの非対象

- 足切りの具体的な個数閾値
- 揺らしテストの正確な振幅・波形パラメーター
- その他、本番の評価関数・シミュレータ内部の非公開パラメーター全般

これらについては「範囲内でのロバスト性確認」までは行うが、「本番スコアに最も近い値を
特定する」という形の逆算は行わない。理由は本ファイル冒頭の禁止事項による。

## 4. 公式値は「本物の判定閾値」であって planner の近似モデルが使ってよい値ではない(Phase75〜76)

§2 の内包判定マージン **5mm**・経路干渉の余裕 **1.5cm** は、**本番シミュレータ
(pybullet の 1cm 刻みシミュレーション、`results/phase61_report.md` §3-1)が使う本物の
判定閾値**である。`agents/mysolver` 側の `geometry.py` は同じ判定を配置前に AABB による
解析的近似で自己再現しているだけなので、**近似モデルの誤差を吸収する余分なマージンが
必要**であり、公式値をそのまま代入すると成績が落ちる。

Phase75 で3定数を公式値へ1段近づけた本番結果:

| 定数 | 変更 | public | num_placed% | 判定 |
|---|---|---:|---:|---|
| `INCLUSION_MARGIN` | −0.012 → −0.008 | 57.180 | — | **完全に無効(−0.005)** |
| `SAFETY_MARGIN_XY` | 0.022 → 0.018 | 54.00 | — | **−3.19** |
| `REST_CLEARANCE` | 0.016 → 0.012 | **9.19** | 36.42 | **−48.0。崖だった** |

**→ 現行の(公式値より約7mm 保守的な)値のほうが実測で良い。** `MAX_SUPPORT_CENTROID_OFFSET`
だけは例外で、あれは判定閾値の近似誤差ではなく「支持の質」という別種の自制のため
緩める方向に利得があった(Phase74)。

### 足切りは実在する(rest012 が直接証拠)

`REST_CLEARANCE` を 0.012 に詰めた `rest012`(配置率 **36.42%**)では、
fill 22.01 に対し cog 3.02 / stability 4.17 / placement 4.50 / soft_item 5.00 と、
**fill 以外の4指標が 3〜5 まで崩落した。** §2 の「積み付けられた手荷物の数が一定数
以上にならないと fill 以外は0点」がそのまま観測された形。足切りの効果は桁違いに大きい。
**ただし閾値そのもの(何個で発動するか)は逆算しない**(本ファイル冒頭の禁止事項)。
