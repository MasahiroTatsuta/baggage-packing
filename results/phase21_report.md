## 0. エグゼクティブ・サマリ

- **【ターゲット1・完了・本フェーズの主成果】** 26シーンの配置済み荷物 **574件を全数監査**し、
  fill に計上されなかった体積を「どの面をどれだけ突き抜けたか」で相互排他に分類した。
  結果は極端に一極集中している:

  | 原因 | strict の計上漏れ体積シェア | 置けた体積に対する比 |
  |---|---|---|
  | **(a) 床直置き(剛体・軸平行)** | **96.4%** | 35.7% |
  | ソフト貨物の床へのめり込み | 3.3% | 1.2% |
  | 奥面 | 0.3% | 0.1% |
  | **(b) 傾いて壁・天井・切り欠きに接触** | **0.0%** | 0.0% |
  | **(c) 棚に接触** | **0.0%** | 0.0% |
  | **(d) 他の荷物に押されて移動** | **0.0%** | 0.0% |

  突き抜けた面別では **floor が 99.7%**、back が 0.3%。**天井・切り欠き・側壁による除外は1件も無い。**
- **【仮説(b)は測定不能なほど小さいのではなく、原理的に起きていない】** 配置済み574件の
  傾き角は **median 0.02° / p90 0.31° / 最大 3.72°** で、**5°以上は0件**。指示にあった
  ターゲット2の候補(壁際配置の内側寄せ・支持面の平坦性優先・傾きやすい姿勢の回避)は、
  **狙う対象が実測上存在しない**。
- **【loose では計上漏れがほぼ消える】** 計上率は strict **0.629** に対し loose **0.993**。
  loose での漏れは 0.388 m³(置けた体積の0.7%)で、**その全量がソフト貨物の深いめり込み**。
  検算: `fill_loose − fill_strict = 13.73pt` に対し床層の体積換算 **13.49pt** でほぼ一致し、
  **strict/loose の差の実体は床層そのもの**であることが確定した(§2.3)。
- **【機序は厳密に特定できた】** 床面の判定式は `dot_floor = thickness − bottom_z`。軸平行の
  荷物が内床面に接地すると `dot = 0` となり、判定 `0 > −0.005` で**必ず**除外される。
  つまり **fill_strict に計上されるには内床面から5mm以上浮いている必要があり、
  物理沈降は必ず支持面まで落とすので床接地荷物は構造的に永久に計上されない**(§2.1)。
- **【ターゲット2・指示された目標は幾何的に到達不能と判明】** 指示の「計上率0.85 →
  fill_strict 31.6」は床層を **8.149 m³ 以下**に圧縮することを要求するが、
  実測の被覆率(53.3%)を維持したまま**手持ちの最も薄い荷物で床を作った場合の下界が
  13.316 m³** であり、目標値はこの下界を大きく下回る。**計上漏れ36%のうち約2/3は
  削減不能な土台コスト**であって未開拓のレバーではない(§3.2)。
- **【ターゲット2・機序を直接検証して棄却】** 残る +4.24pt の上限を取りにいく唯一の機序
  「薄い荷物を床に、厚い荷物を上段に」を、**エージェント無改造のまま手組み順序を実
  エピソードに流して**検証した。結果、`thin_first` は床層を薄くする一方で
  **置けた体積が 2.491 → 1.768 m³ に崩壊**し、fill_strict は **17.82 → 17.57(改善せず)**、
  fill_loose は **36.91 → 27.35(大幅悪化)**。上限の前提「解放した体積を上段に積み直せる」が
  成り立たないことを実測で確認した(§3.3)。
- **【結論】** 指示の分岐「(a)床直置きが支配的な場合は測定結果と選択肢の整理までを成果とし、
  実装は次フェーズに回してよい」に該当する。**コード変更は行わない**(agents/ は Phase20 と同一)。
  加えて、本フェーズは選択肢の整理に留まらず**最有力候補の機序を実測で棄却**したので、
  次フェーズがこの方向に時間を投じるべきでないことまで確定できた(§5)。

## 2. ターゲット1:計上漏れの原因分解

### 2.1 判定式と分類の設計(`tools/phase21_fill_audit.py`)

`src/ground_handling/evaluator.py` の `calculate_fill_rate` は、荷物の8角点それぞれについて
コンテナの各面 f で `dot_f = n_vec_f ・ (corner − point_f)` を計算し、**どれか1つでも**
`dot_f > inclusion_margin` なら「内包していない」として fill から除外する。
したがって除外の原因は「どの面の、どの角が、どれだけ超えたか」で完全に特定できる。

コンテナの面は実測で7面と確認した(推測ではなく、実際に `n_vecs`/`points` を出力して同定):

| 面 | 法線 | 代表点 | 意味 |
|---|---|---|---|
| face0 | (0,0,−1) | z=thickness | **内床面** |
| face1 | (+1,0,0) | x=+0.960 | +X側壁 |
| face2 | (0,0,+1) | z=1.570 | 天井 |
| face3 | (−1,0,0) | x=−0.960 | −X側壁 |
| face4 | (−0.673,0,−0.740) | — | 開口部脇の切り欠き斜面 |
| face5 | (0,−1,0) | y=−0.725 | 手前(開口部)面 |
| face6 | (0,+1,0) | y=+0.685 | 奥面 |

**床面の機序(厳密)**: face0 の dot は `dot_floor = thickness − bottom_z`。
軸平行の荷物が内床面に接地すると `bottom_z = thickness` なので `dot_floor = 0`。
判定は `0 > −0.005` なので **除外される**。逆に計上されるには
`bottom_z ≥ thickness + 0.005`、つまり **内床面から5mm以上浮いている**必要がある。
`planner` は目標zを支持面から `REST_CLEARANCE=16mm` 浮かせるが、配置後の物理演算
(`settle_wait_step=300`)で必ず支持面まで落ちるため、**床接地荷物がこの5mmを満たすことは
構造的にあり得ない**。

分類は、面ごとの超過量 `excess_f = max_corner(dot_f) − margin` を求め、
**最大の超過を出した面**を primary として体積を按分する(相互排他)。そのうえで
傾き角・床からの高さ・目標位置からのずれを属性として併記し、(a)〜(e)に振り分けた。
**件数ではなく体積シェアで集計している**(fill は体積ベースのため)。

### 2.2 結果(26シーン、配置済み574件、置けた体積 54.327 m³)

**STRICT (inclusion_margin = −0.005)**: 計上体積 34.197 m³ / **計上率 0.629** / 計上漏れ 20.131 m³

| 原因 | 体積 | 計上漏れに対する% | 置けた体積に対する% |
|---|---|---|---|
| **(a) 床直置き(剛体・軸平行)** | 19.413 m³ | **96.4%** | 35.7% |
| ソフト貨物の床へのめり込み | 0.664 m³ | 3.3% | 1.2% |
| 奥面(back) | 0.054 m³ | 0.3% | 0.1% |
| (b) 傾き / (c) 棚 / (d) 移動 | 0.000 m³ | **0.0%** | 0.0% |

突き抜けた面別: **floor 99.7% / back 0.3%**。

**LOOSE (inclusion_margin = +0.01)**: 計上体積 53.939 m³ / **計上率 0.993** / 計上漏れ 0.388 m³
— **全量がソフト貨物の深いめり込み**(3件のみ、いずれも `is_soft=True`)。

**「(e) その他(床面)」の正体を追跡した結果、11件すべてがソフト貨物だった。**
底面が内床面より **5.5〜20.1mm 沈み込んでいる**(`bottom_above_floor` が −0.0055〜−0.0201)。
`contactStiffness` が低いソフト貨物が床にめり込み、`dot_floor = thickness − bottom_z > 0` が
より大きくなって落ちている。したがってこれも実質「床面由来」であり、
**床面が計上漏れの 99.7% を占める**という結論は動かない。

**傾きは原理的に起きていない**: 配置済み574件の傾き角(各ローカル軸が最も近いワールド軸から
ずれる角度の最大値)は **median 0.02° / p90 0.31° / 最大 3.72°**、**5°以上は0件**。
`env.build()` と `settle_wait_step` を経ても荷物はほぼ完全に軸平行に落ち着く。
よって仮説(b)は「小さい」のではなく**発生していない**。

### 2.3 strict/loose の差の実体は床層そのもの(検算)

| 量 | 値 |
|---|---|
| 総コンテナ有効体積 | 143.855 m³ |
| 置けた体積 | 54.327 m³ |
| fill_strict(= 計上体積/総容積) | **23.77** |
| fill_loose | **37.50** |
| 差 | **13.73pt** |
| 床層(床接地荷物)の体積 | 19.413 m³ = **13.49pt 相当** |

差 13.73pt と床層 13.49pt がほぼ一致する(残差 0.24pt はソフト貨物のめり込み分)。
**fill_strict は構造的に「床層より上の体積」しか測っていない。**
また Phase20 の suite 実測(fill_strict 23.74 / fill_loose 36.65)と本監査(23.77 / 37.50)は
整合しており、監査の妥当性を裏づける。

### 2.4 床層の実像

| 指標 | 値 |
|---|---|
| 床層の被覆率(床面積に対する足跡面積) | 平均 **53.3%**(37.3〜64.9%) |
| 床層荷物の配置高さ(z方向AABB) median | **0.273 m** |
| 2層目以上の荷物の配置高さ median | 0.335 m |
| 全荷物の配置高さ median | 0.321 m |

**床層はすでに全体より薄い荷物で構成されている**(0.273 < 0.321)。
つまり「薄い荷物を床に回す」という発想は、現行の探索が**すでに部分的に実現している**。

### 2.5 副次的に検定して棄却した仮説

「床層は固定費であり、追加で置いた体積は全部計上される(=限界計上率1.0)」という
仮説を検定したが**棄却**された。

- コンテナ1台あたり床層体積は **0.219〜0.993 m³**(平均0.506、std 0.214)と大きくばらつき、固定ではない。
- 回帰 `counted = 0.621 × placed + 0.017` で、**限界計上率 0.621 ≒ 平均計上率 0.629**。
- コンテナ1台あたり置けた体積と計上率の相関は **r = +0.130**(ほぼ無相関)。

つまり床層は置けた体積に比例して増える。「床を覆い終われば以降は全部計上される」わけではない。

## 3. ターゲット2:計上体積を増やせるか

### 3.1 実測から自動的に消えた選択肢

指示にあった (b) 系の候補(壁際配置の内側寄せ / 支持面の平坦性を優先する候補選択 /
傾きやすい姿勢の回避)は、**傾きによる除外が0件・天井/切り欠き/側壁による除外が0件**
であるため、**改善余地がゼロ**である。実装しても定義上1ミリも動かない。

### 3.2 指示の目標(計上率0.85)は幾何的に到達不能

床層は「積み上げの土台」として幾何的に必要であり、体積をゼロにはできない。
実測の被覆率(53.3%)を維持したまま、**手持ちの配置済み荷物のうち最も薄いものから
順に床を覆った場合**の床層体積の下界を計算した:

| | 床層体積 | 計上率 | fill_strict |
|---|---|---|---|
| 現状 | 19.413 m³ | 0.629 | **23.77** |
| **最薄構成の下界**(被覆53.3%維持) | **13.316 m³** | **0.742** | **28.01(+4.24pt)** |
| 床層が消える理想極限(=strictがlooseに一致) | 0 | 1.000 | 37.77 |
| **指示の目標 0.85** | **8.149 m³ が必要** | 0.85 | 31.6 |

**目標 0.85 が要求する 8.149 m³ は、下界 13.316 m³ を大きく下回る。**
したがって「計上率0.85」は現行の配置能力・荷物構成のもとでは**幾何的に到達不能**である。
指示の見立て「36%が未開拓のレバー」は、**その約2/3が削減不能な土台コスト**である点を
織り込むと成立しない。残る上限は **+4.24pt**(それでも ±0.90 のノイズ床や
Phase20 の ρ-test 天井 1.14pt より大きい)。

### 3.3 残る唯一の機序を直接検証 → 棄却

+4.24pt を取りにいく機序は1つに絞られる:**薄い荷物を床層に、厚い荷物を上段に回す**。
これを**エージェントを一切変更せず**に検証した。online の `_score` は
`z_term = −world_z × 12.0` で低い位置を強く選好するため、
「薄い荷物を先に流す」= 床層が薄くなる、という対応が成り立つ。
手組みの順序を `env.set_item_order` で実エピソードに流し込み、8シーンで比較した。

| 順序 | fill_strict 平均 | fill_loose 平均 | 置けた体積 平均 |
|---|---|---|---|
| `thin_first`(最小寸法の昇順) | **17.57** | **27.35** | **1.768** |
| `thick_first`(最小寸法の降順) | 16.21 | 36.03 | 2.369 |
| `volume_desc`(体積降順、現行戦略の素の形) | **17.82** | **36.91** | **2.491** |

**`thin_first` は fill_strict でも改善しない(17.57 < 17.82)うえ、fill_loose を
36.91 → 27.35 と大幅に悪化させる。** 原因は明確で、**置けた体積が 2.491 → 1.768 m³ に
崩壊している**(配置個数は逆に増える: 例 A04 で 13個→36個)。薄い荷物を先に大量に
流すと容器が薄物で埋まり、後から来る厚い荷物が入らなくなる。

§3.2 の上限 +4.24pt は「床層から解放した体積を上段に積み直せる」ことを前提にしていたが、
**その前提が実測で成り立たない**。床層を薄くすること自体は達成できても、
浮いた体積を上に積む能力が伴わないため、計上体積は増えない。

> 留保: ここで試したのは大域的な単純ソートであり、「第1層だけ薄物、以降は厚物」という
> より精緻な層別戦略が同じ結果になるとは限らない。ただし (1) 現行の床層はすでに
> 全体より薄い荷物で構成されている(§2.4)、(2) 単純版は置けた体積を29%失う、
> という2点から、この方向の期待値は低いと判断する。

### 3.4 唯一のレジーム非依存な損失:ソフト貨物の床へのめり込み

計上漏れのうち、**strict でも loose でも失われる**のはソフト貨物の床へのめり込みだけである。

| | 体積 | fill 換算 |
|---|---|---|
| strict | 0.664 m³ | 0.46pt |
| loose | 0.388 m³ | 0.27pt |

ソフト貨物を床に直置きせず1段上に置けば回避できる可能性があるが、
**いずれも 26シーン平均のノイズ床(±0.90pt)を下回る**ため、
Phase18/19/20 の教訓(小さな期待値のために探索へ介入すると崖を踏む)に照らして
本フェーズでは手を付けない。

26シーンの再計測は不要(Phase20 の測定結果がそのまま現状である)。

## 4. 本フェーズで確定した構造的理解

**fill_strict の正体**: 「置けた体積 − 床接地層の体積」。床接地層は
(i) 積み上げの土台として幾何的に必要、(ii) 置けた体積に比例して増える、
(iii) すでに平均より薄い荷物で構成されている。したがって

```
fill_strict ≈ (置けた体積 − 床層) / 総容積
            ≈ 0.63 × 置けた体積 / 総容積
```

という関係が成り立ち、**fill_strict を上げる主要な道は「置けた体積そのものを増やすこと」**に
戻る。計上率は独立に動かせるレバーではなく、置けた体積に対してほぼ一定の係数である。

**レジーム問題の重み**: loose なら計上率は 0.993 で、**そもそも回収すべき36%は存在しない**。
本フェーズの分析全体が意味を持つのは本番が strict の場合だけである。
Phase13 で「判別不能」と結論したが、Phase16 の予算掃引は
**strict と loose が逆方向に動いた唯一の識別可能な観測**(strict +1.15 / loose −2.90 で
public 50.25→51.00)であり、public が strict を追跡することを示す n=1 の証拠として残る。

## 5. 次フェーズへの申し送り

1. **床層の計上漏れを追う方向は打ち切りを推奨。** 上限が +4.24pt しかなく(§3.2)、
   その上限を実現する唯一の機序も実測で棄却された(§3.3)。指示の目標 0.85 は
   幾何的に到達不能。
2. **レバーは「置けた体積を増やすこと」に戻る。** Phase20 §2.3 で候補順序による
   実fillスプレッドが平均 19.19pt と大きいことは分かっているので、
   置けた体積(=配置能力)にはまだ余地がある。Phase19 の申し送り
   「高速化で得た余力を探索構造の見直しへ」と方向が一致する。
3. **本フェーズで消えた選択肢を記録しておく**(再訪しないために):
   - 傾き対策(内側寄せ・平坦性優先・姿勢制限): 傾き由来の除外が **0件**なので効果ゼロ。
   - 一律マージン強化(`INCLUSION_MARGIN`): Phase11 で既に棄却済み。
   - 薄物を床に回す順序戦略: §3.3 で実測棄却(置けた体積が29%崩壊)。
   - 代理関数の較正改善: Phase20 §3 で構造的に棄却済み。
4. **ソフト貨物の床めり込み(§3.4)はレジーム非依存の唯一の損失**だが 0.27〜0.46pt で
   ノイズ床未満。他に大きな施策が無くなった段階で、リスクの低い形(例: ソフト貨物の
