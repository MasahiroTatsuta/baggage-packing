## 2. ステップ0(2): 公式の内包判定規則に床面が含まれるか

### 2.1 面リストの構成

`src/ground_handling/utils.py:200-213`(`write_open_cut_corner_cup_obj`)が面リストを返す:

```python
for i in range(m):                      # 内側の2Dポリゴン = 側面(斜め切り欠きを含む)
    points.append(inner2d[i]+[0])
    n_vecs.append(n_vec)
points.extend([[0,0,z1],[0,0,zi]])      # z1 = 上端, zi = 内底
n_vecs.extend([[0,0,1],[0,0,-1]])       # 外向き法線
```

つまり面の集合は **側面(奥/手前/左/右/斜め切り欠き) + 天井 + 内床面**であり、
**床面は公式の判定対象に含まれている**。

`Evaluator.calculate_fill_rate`(`evaluator.py:51-60`)は8隅点それぞれについて全面との
内積を取り、`np.any(dots > self.inclusion_margin)` なら除外する。
**床面だけを特別扱いする分岐は無い。**

### 2.2 床接地が構造的に除外される機序(貫入は無関係)

床面の外向き法線は `[0,0,-1]`、代表点は `[0,0,zi]` なので、隅点 `corner` に対して

```
dot_floor = [0,0,-1] · (corner − [0,0,zi]) = zi − corner_z
```

計上されるための条件は `dot_floor <= inclusion_margin = −0.005`、すなわち

```
corner_z >= zi + 0.005      (底面が内床面から 5mm 以上浮いている)
```

| 状態 | `corner_z` | `dot_floor` | `−0.005` 判定 | `+0.01` 判定 |
|---|---|---|---|---|
| 床から5mm以上浮上 | `>= zi+0.005` | `<= −0.005` | ✅ 計上 | ✅ 計上 |
| 床にちょうど接地(貫入0) | `= zi` | `0` | ❌ 除外 | ✅ 計上 |
| 床へ3mm貫入 | `= zi−0.003` | `+0.003` | ❌ 除外 | ✅ 計上 |
| 床へ10mm超の貫入 | `< zi−0.010` | `> +0.010` | ❌ 除外 | ❌ 除外 |

**重要**: 貫入量が厳密に0でも除外される。**貫入(interpenetration)は原因ではない。**
これは沈み込みの問題ではなく、`dot=0` に対して `margin=−0.005` を課すという
**マージン演算そのものの帰結**である。

物理沈降は必ず荷物を支持面まで落とすため、「床の上5mmに浮いたまま静止する」状態は作れない。
**したがって床接地荷物は、配置アルゴリズムを何に変えても永久に計上されない。**

### 2.3 判定基準への当てはめ

| 判定 | 条件 | 本フェーズでの成否 |
|---|---|---|
| (A) 失われた体積の50%以上が δ<=15mm かつ側面/奥面/手前面で回収可能 | — | ❌ Phase21実測で面別の床面が99.7%、側面系は0.3%(§3.1) |
| **(B) 床直置きが支配的で、貫入量が5mmよりはるかに小さい** | — | ✅ **該当**。ただし「貫入量が小さいから」ではなく**貫入量が0でも除外されるから**であり、(B)の想定よりさらに強い形で閉じている |
| (C) 床直置きが支配的で、貫入量が3〜8mmでばらついている | — | ❌ **前提から不成立**。貫入量は判定に無関係(§2.2) |
| (D) いずれにも当てはまらない | — | ❌ (B)に該当 |

**判定: (B)。このレバーは決定的に閉じる。**

## 4. 12.18pt を「7.3 public相当のプール」と換算できない理由

### 4.1 fill_loose は「別の到達可能な状態」ではない

`fill_strict` と `fill_loose`(`tools/measure_regime.py`)は、**同一エピソードの同一の最終配置**に対して
`Evaluator.calculate_fill_rate` を margin 違いで2回呼んだだけの値である
(この2回呼びは Phase12 で「1エピソード=1シミュレーションで両レジームを得る」ために導入された)。

つまり 12.18pt は「あと少し工夫すれば取れる体積」ではなく、
**同じ結果を別の物差しで測ったときの目盛りの差**である。

### 4.2 evaluator と validator は常に同じ margin を共有する

`env.py:51` の配線により、`inclusion_margin` は**採点(evaluator)と合法性判定(validator)の
両方を同時に動かす**。したがって考えうる世界は2つしかない:

| 世界 | validator への影響 | evaluator への影響 | 12.18pt の扱い |
|---|---|---|---|
| `margin = −0.005`(配布configの実値) | 現行どおり厳しい | 床接地は除外 | **構造的に回収不能**(§2.2) |
| `margin = +0.01` | **今より緩い配置が合法になる** | 床接地も計上される | **既に計上済み**。回収すべきギャップが存在しない |

**どちらの世界でも 12.18pt は取りに行けるプールにならない。**

これは Phase12〜13 以来の未解決課題「本番の内包判定レジーム(厳/緩)が未確定」に対する
部分的な前進でもある。レジームがどちらかは依然として確定できないが、
**fill_strict と fill_loose を『独立に追える2つの目標』として扱うのは誤り**であることが
構造から確定した。

### 4.3 Phase26 でギャップが +4.20 広がったことの解釈

指示には「壁積みがギャップを 12.18 → 16.38 に広げた。固定の物理定数ではなく操作可能な量である
以上、逆向きの操作にも反応する見込みがある」とあった。**この推論は成立しない。**

ギャップが操作に反応すること自体は事実だが、反応の方向は**片側にしか開いていない**:

- ギャップを**広げる**ことはできる(壁積みが実証した。壁際・床際の配置を増やせばよい)
- ギャップを**縮める**には床接地荷物を減らすしかないが、床層は土台として幾何的に必要で、
  Phase21 が「薄物を床へ」という唯一の機序を実測で棄却済み(置けた体積が29%崩壊)

つまり「操作可能」であっても**有利な向きには動かせない**。
なお Phase26 の壁積みは fill_strict を −2.96 悪化させており、
**ギャップを広げる操作は同時に計上体積そのものを減らしている**。

## 5. 判定と、Phase28 で何をやるべきかの提案

### 5.1 判定

**(B) 床直置きが支配的で、マージン演算上、床接地が構造的に除外されている。このレバーは
決定的に閉じる。**

(B) の当初定義は「貫入量が5mmよりはるかに小さい」だったが、実際には**貫入量が0でも除外される**
ため、想定よりさらに強い形で閉じている。

### 5.2 Phase28 への提案

このレバーが閉じたことで、残る方向は Phase24 から持ち越しの1本に絞られる。

**推奨: 順序探索の目的関数側で「置いた後にどんな通路が残るか」を事後評価する。**

根拠:
- 空きの **38.8%** が搬入経路の封鎖(Phase24 で厳密に測り直した値。それ以前の自分の測定は
  42%の過小評価だった)。空きの最大要因であり、**未着手のまま残っている唯一の大きな量**である。
- `corridor_penalty` の枠内では解けないことが Phase24 で判明済み。理由は myopia:
  `corridor_penalty` は**既に置かれた障害物の上の通路しか守れない**のに対し、封鎖の主因である
  中間高さ帯・上部の通路は**その後の積み上げで初めて生まれる**。
- Phase24 の厳密判定は疎な位置集合に対するAABB判定として**実装済みで十分に速い**ので、
  `simulate.py` の目的関数を「置けた体積」だけでなく「残った空間のうち到達可能な割合」でも
  測る形に拡張できる。

**注意点(Phase25b/26 の教訓の申し送り)**:
- 代理関数の順位相関は Spearman 0.71 がボトルネックであり、目的関数を変えることは
  **この順位を変える**ことを意味する。σが大きく出やすい変更なので、σ/SE/t(t>2)での
  判定を厳格に適用すること。
- 絞り込み計測を行う場合、標本は対象群から**機械的な規則**(シーンID昇順など)で取ること。
  Phase26 では「効果が最大のシーン」を選んだ結果 +3.99 と出たが、26シーン全体では −2.96 だった。

**やってはいけないこと**:
- `boundary_term` の重み調整によるギャップ回収。§2.2 のとおり床接地は margin 演算で
  除外されるので、スコア関数側で何をしても計上されない。加えて Phase18 で
  「単一大域重みは崖の位置がシーン間で逆転し較正不能」と結論が出ている。
- 候補生成段階での幾何的内寸縮小(判定(A)の打ち手)。面別で側面系は 0.3% しかないため、
  回収上限は 12.18pt × 0.003 ≒ **0.04pt** で、実装コストに見合わない。
