## 0. エグゼクティブ・サマリ

- **【背景】** Phase23(ビームサーチ b=3)は26シーン平均で fill_strict **+1.95pt** という
  一見明確な改善だったため採用したが、**実際の提出フィードバックは public **−0.45**** だった。
  ユーザー確認済みの提出履歴では、public のベストは Phase16 時点の **51.30** であり、
  そこから直近3フェーズで **net −0.75** 後退している。26シーン平均という一次元の指標だけでは、
  「別シーン集合(隠しテスト)に一般化するかどうか」を見誤ることが実測で裏付けられた。

- **【採否基準の改訂】** 26シーン平均の改善だけで採否を決めるのをやめ、以下を必ず報告・判定に
  使うことにした(`tools/phase25a_stats.py` を新規作成):
  1. シーン別効果(ペア差分 d_i = after_i − before_i)の標準偏差 **σ**
  2. 標準誤差 **SE = σ/√26**
  3. **t値 = 平均差分 / SE**(対応のあるt検定)。**採用の目安は t > 2**。
  4. 「ノイズ床±0.90」(`tools/compare_suite.py`)は**同一シーンの再実行ばらつき**であり、
     **別シーン集合への一般化誤差ではない**ため、両者を混同せず併記する。

  この基準で Phase23(b=3)を再計算すると **+1.95 ± 1.20(SE)、t=1.62** で、
  **t>2に届かず不採用相当**だった(§1.2で再現)。実際の public が −0.45 だった事実と整合する。

- **【ターゲット1: BEAM_WIDTH を1へ復帰】** `BEAM_WIDTH` の既定を **3→1**(Phase22相当)に戻した。
  26シーンで再測定した fill_strict は **23.736**(Phase23報告書に記載の b=1 値 23.74 と実質完全
  一致、diff 0.004)で、リグレッション(逆行)が正しく機能していることを確認した(§1.1)。

- **【ターゲット2: UNITS_PER_SEC の26シーンA/B — 不採用】** BEAM_WIDTH=1 に固定し、
  `UNITS_PER_SEC` を **1.05e7**(現行)と **1.55e7**(Phase17時点の値)で26シーンA/Bした。

  | 指標 | 1.05e7 | 1.55e7 | 差 |
  |---|---|---|---|
  | fill_strict | 23.736 | 24.413 | +0.677 |
  | fill_loose | 36.655 | 36.590 | −0.065 |
  | cog_score | 65.687 | 64.954 | −0.733 |
  | stability_score | 98.304 | 98.243 | −0.061 |
  | placement_score | 100.00 | 100.00 | ±0.00 |
  | soft_item_score | 100.00 | 100.00 | ±0.00 |

  fill_strict の26シーン平均差分は **+0.677**——旧基準の「ノイズ床±0.90」にすら届かない
  水準であり、新基準でも **σ=5.066, SE=0.994, t=0.682** で **明確に不採用**(t>2を大きく下回る)。
  シーン別の差分は **+10.74〜−9.73** と符号が激しく反転しており(§2.2)、
  Phase23(b=3)と同型の「高分散ゆえ一般化しない」パターンが再現した。**`UNITS_PER_SEC=1.05e7`
  を据え置く。**

- **【安全弁・決定性は1.55e7でも確保されていた】** 26シーン中の最重量シーンで
  optimize実測 **最大114.68秒**(HARD_WALL_LIMIT=165s に対し十分な余裕)。さらに最も重い
  上位6シーンを2反復ずつ再測定したところ、**全6シーンで fill_strict std=0.0000**
  (安全弁は発火せず決定性は保たれる、§2.3)。つまり **1.55e7の不採用は「危険だから」ではなく
  「分散が大きく一般化する保証がないから」**であり、両者を区別して報告する。

- **【確定した最良構成】** `BEAM_WIDTH=1` かつ `UNITS_PER_SEC=1.05e7`(=現在のコード既定値、
  Phase22相当)を **Phase25a時点のアンカー構成**として確定した。以後のフェーズはこの構成からの
  diffで26シーン平均・σ・SE・tを報告する。

## 1. ターゲット1: BEAM_WIDTH の既定を1へ戻す

### 1.1 復帰の確認

`agents/mysolver/ordering.py` の `BEAM_WIDTH = int(os.environ.get('MYSOLVER_BEAM_WIDTH', '3'))`
を `'1'` に戻した。26シーン(`tools/measure_regime.py --repeats 1`)で測定した結果:

| 指標 | Phase23報告書のb=1値 | Phase25a再測定(b=1) | 差 |
|---|---|---|---|
| fill_strict | 23.74 | 23.736 | −0.004 |
| cog_score | 65.69 | 65.687 | −0.003 |
| stability_score | 98.30 | 98.304 | +0.004 |
| placement_score | 100.00 | 100.00 | ±0.00 |
| soft_item_score | 100.00 | 100.00 | ±0.00 |

小数第2〜3位まで完全に一致しており、決定的な探索(Phase17で確立)である以上当然の結果だが、
**BEAM_WIDTHの既定変更が意図通り「Phase22相当の状態」を再現していること**を裏付ける。
このファイル(`results/phase25a_suite_beam1.json`)を以後のA/Bの `before`(=UNITS_PER_SEC=1.05e7側)
としてそのまま流用した(BEAM_WIDTH=1・UNITS_PER_SEC=1.05e7 は現行既定そのものであるため、
再実行せず同一データを使い回すのは二重計測を避けるための正当な最適化)。

### 1.2 参考: Phase23(b=3)を新基準で再計算

新しく作った `tools/phase25a_stats.py` で、Phase23報告書の値が新基準でどう評価されるかを
本フェーズのb=1データを基準にして検算した:

シーン別差分は `+11.77`(A03)から `−14.78`(D01)まで振れており、これが実際の public −0.45

## 2. ターゲット2: UNITS_PER_SEC の26シーンA/B(BEAM_WIDTH=1固定)

### 2.1 背景

Phase19で `UNITS_PER_SEC` を1.55e7→1.05e7へ下げたのは、当時 `CANDIDATE_BUILD_COST` の
再較正候補(8.64)と**同時に**変更した場合にのみ `C02` で placement 100→85.71 の崖が
起きるという安全弁回避策だった(`CANDIDATE_BUILD_COST` は据え置き、`UNITS_PER_SEC` のみ
1.05e7へ)。Phase24の実測(optimize最大53.48秒、上限170秒)では大きな余裕があることが
分かっており、1.55e7に戻せば同じ名目秒でユニット予算が約1.48倍(=1.55/1.05)になり、
Phase19で失った fill を回復できる可能性があった。この仮説をBEAM_WIDTH=1・26シーンA/Bで検証した。

### 2.2 結果

`tools/phase25a_ups_ab.sh 1.05e7` / `tools/phase25a_ups_ab.sh 1.55e7`(BEAM_WIDTH=1、
`configs/gen/suite_*.json` 26シーン、repeats=1)。

| 指標 | 1.05e7(現行) | 1.55e7 | 差 |
|---|---|---|---|
| fill_strict | 23.736 | 24.413 | **+0.677** |
| fill_loose | 36.655 | 36.590 | −0.065 |
| cog_score | 65.687 | 64.954 | −0.733 |
| stability_score | 98.304 | 98.243 | −0.061 |
| placement_score | 100.00 | 100.00 | ±0.00 |
| soft_item_score | 100.00 | 100.00 | ±0.00 |

`tools/phase25a_stats.py --metric fill_strict` によるシーン間統計:

```
26シーン平均差分        : +0.677
シーン別効果の標準偏差σ  : 5.066
標準誤差 SE=σ/√26     : 0.994
t値 (mean/SE)          : 0.682
判定                    : 不採用相当 (|t| <= 2.0)
```

**旧基準(ノイズ床±0.90)でもそもそも改善域に届いていない**(+0.677 < 0.90)。
新基準の t=0.682 は Phase23(t=1.62)よりさらに弱く、**判定は明確に不採用**。

シーン別の内訳(降順、抜粋):

| シーン | 1.05e7 | 1.55e7 | 差 |
|---|---|---|---|
| A07_1c_40_bulky | 28.07 | 38.81 | **+10.74** |
| A05_2c_80_prio | 11.09 | 21.83 | **+10.74** |
| P03_A_2c_pre8_prio | 12.24 | 20.73 | +8.48 |
| … | | | |
| D03_A_2c_60_prioheavy_cont | 30.86 | 21.13 | **−9.73** |
| A01_1c_40_plain | 27.22 | 18.49 | −8.73 |
| C03_2c_80_prio | 40.92 | 32.21 | −8.71 |

12シーンは全く動かない(予算が律速していない、または探索が同じ局所解に収束)一方、
残り14シーンは +10.74〜−9.73 の範囲で大きく振れる。予算を増やすと「同じ壁時計内で
より多くの組合せを試す」ため、Phase16以来くり返し観測されている「探索パラメータは
連続的なダイヤルではなく、貪欲構築+リスタートという離散探索に対して別の局所解への
スイッチとして作用する」現象(`results/phase16_report.md`〜`phase19_report.md`)が
そのまま再現している。**予算を増やせば単調に改善する、という直感は成り立たない。**

### 2.3 実測時間と安全弁・決定性の確認

| | 1.05e7 | 1.55e7 |
|---|---|---|
| optimize実測: 平均 | 44.17s | 63.18s |
| optimize実測: 最大 | 80.01s | 114.68s |
| policy実測: 平均 | 0.413s | 0.438s |
| policy実測: 最大 | 1.81s | 1.73s |

いずれも `HARD_WALL_LIMIT=165s`(optimize)・`8s`(policy)に対して十分な余裕がある。
1.55e7で最も重かった上位6シーン(`A06_1c_40_small`, `P05_C_2c_pre8_shelfprio`,
`C02_2c_55_shelfprio`, `A02_1c_80_plain`, `P06_A_1c_pre12_dense`, `C01_1c_40_shelf`)を
**2反復ずつ**再測定し、決定性(=安全弁が発火していないこと)を直接確認した:

| シーン | fill_strict std(2反復) | optimize実測 平均/最大 |
|---|---|---|
| A06_1c_40_small | 0.0000 | 130.72s / 136.44s |
| P05_C_2c_pre8_shelfprio | 0.0000 | 91.29s / 92.22s |
| C02_2c_55_shelfprio | 0.0000 | 95.26s / 96.13s |
| A02_1c_80_plain | 0.0000 | 96.81s / 100.34s |
| P06_A_1c_pre12_dense | 0.0000 | 83.26s / 84.97s |
| C01_1c_40_shelf | 0.0000 | 92.17s / 93.08s |

**全6シーンで std=0.0000**(=同一入力から同一出力、安全弁は発火していない)。
最重量シーン(`A06_1c_40_small`)でも最大136.44秒で `HARD_WALL_LIMIT=165s` に対し
約29秒の余裕を残しており、1.55e7への変更自体はタイムアウト・決定性の観点では安全である。

**したがって1.55e7の不採用理由は「危険だから」ではなく「シーン間分散が大きく、
26シーン平均の改善が別シーン集合(隠しテスト)へ一般化する統計的根拠がないから」**である。
この区別は本フェーズの採否基準改訂の核心であり、`agents/mysolver/planner.py` の
`UNITS_PER_SEC` 定義コメントにも明記した。

## 5. 次フェーズへの示唆

- **σが大きい変更は個別に疑う**: Phase23(t=1.62)・本フェーズのUNITS_PER_SEC(t=0.682)の
  いずれも「26シーン平均は改善して見えるが、シーン別の符号が大きく反転する」という共通パターンを
  示した。今後、探索予算・幅など「離散的な局所解のスイッチ」として作用する定数を触る場合は、
  掃引前にこの型のσが出やすいことを前提に、**シーン数を増やしてSEを下げる**か、
  **σそのものを下げる設計**(例: 予算配分をなだらかにする、局所解間のジャンプを減らす)を
  優先すべきである。
- **корridor_penalty の myopia(Phase24)は依然未解決**: 空きの38.8%を占める搬入経路の封鎖は、
  `corridor_penalty` の枠内では解けないことがPhase24で判明している。Phase25a はこの問題に
  着手せず「現状復帰と基準の再構築」に専念したため、次の一手として残る。
- **提出フィードバックとローカル26シーン評価の乖離**: Phase23の実例(26シーン平均+1.95、
  public −0.45)は、ローカルの26シーンスイート自体にも「隠しテストの分布を完全には代表
  していない」誤差が乗っていることを示す。σ/SE/tはこの乖離の一部(シーン間分散)を可視化
  するが、26シーン自体のサンプルサイズの限界(§本文の「シーン数を増やす」提案)は別途の
  課題として残る。
