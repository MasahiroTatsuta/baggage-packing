## 1. 中心仮説と、それを式にしたもの

指示の「階段状スカイライン」仮説をそのまま実装した。

荷物は必ず手前(y=−width/2)から入り、`_evaluate_candidates` の `is_resting` 判定に従って

- 直置き面(床・棚上面)の 0〜50mm 上に底面が来る候補 → **最終高さのまま** Y 方向へ掃引
- それ以外(荷物の上に積む) → **START_Z=80mm 浮上した高さ**で掃引

される。したがって、ある候補が「同じXレーンにあり、自分より奥にある既配置物・棚の**最も低い天面**」より高く手前側に立つと、その低い天面の上に後から荷物を差し込む経路を物理的に塞ぐ。逆に「手前にあるものほど天面が低い」階段状プロファイルを保てば、奥の残容積への通路は原理的に塞がれない。

実装(`planner._corridor_excess`、`_score` から呼ぶ):

```
min_top_behind = min{ 障害物の天面 | 障害物の手前面 >= 候補の奥面 − CORRIDOR_Y_EPS
                                   かつ X範囲が候補と重なる }
excess         = max(0, 候補の天面 − (min_top_behind + CORRIDOR_DEADBAND))
score         -= excess * CORRIDOR_WEIGHT
```

指示どおりの2つの免除条件も入れた。

- **奥に何も無い**(`min_top_behind = inf`)→ 守るべき通路が存在しないのでペナルティなし。
- **奥が既に天井近くまで埋まっている**(`min_top_behind > ceiling_limit − CORRIDOR_MIN_HEADROOM`, 0.10m)→ 通路を残しても何も入らないのでペナルティなし。

計算量は既存の `_contact_bonus` と同形の「障害物ループ × 候補ベクトル」1本の追加のみで、候補配列のサイズも探索回数も増えない(実測タイミングは §4.4)。

## 2. 検証プロトコル(Phase13 §2 のノイズ知見の反映)

Phase13 で確立した「パターンAは単発計測が数pt〜10pt超ぶれる/パターンBは完全に決定的」を踏まえ、次の順で進めた。

1. **決定的なパターンB 5シーン(B01-B04, P04)で重みを先行掃引**(1回計測で足りる)。
2. そこで方向性が出たものだけを **26シーン×3回平均**で判定。
3. さらに **`diagnose_stall` で機序(fail_transport_y)そのもの**を before/after 直接計測。

**副産物として、26シーン平均のノイズ床を実測できた**(本フェーズ以前は per-scene の分散しか分かっていなかった)。**26シーン平均を3回取ると、run間std は fill_strict ±0.45 / fill_loose ±0.39 に収まる**。個々のパターンAシーンは依然 ±5〜10pt ぶれるが、26シーンで平均すると打ち消し合うためである。今後は「26シーン×3回で ±0.4 を超える差なら実効果」という基準が使える。

## 3. ターゲット1:corridor_penalty

### 3.1 不感帯なし初版の重み掃引(パターンB 5シーン、全て決定的)

| W | 0 | 1.5 | 2.0 | 2.5 | 3.0 | 4.0 | 5.0 | 6.0 | 12.0 |
|---|---|---|---|---|---|---|---|---|---|
| fill_strict | 22.33 | 21.83 | 22.96 | **19.46** | 23.21 | **23.50** | 22.72 | 21.94 | 21.83 |
| fill_loose | 30.52 | 29.88 | 30.79 | **27.57** | 31.02 | **31.54** | 31.31 | 30.88 | 31.21 |

**W>0 全水準の平均は 22.18 / 30.53 で、無変更の 22.33 / 30.52 と区別できない。** シーンは完全に決定的なのでこれは計測ノイズではなく、「重みを少し動かすと貪欲の選択が大きく組み替わるが、良くなる方向と悪くなる方向が同確率で起きる」という**カオス的な攪拌**である。Phase6 の back_term の「崖」と同種だが、今回は崖ではなく全域がギザギザだった。

**ここで W=4.0 を最良値として採用していたら、5シーンへの過適合を掴んで26シーン評価で落としていた。** 指示にあった「複数水準を試すこと」がそのまま効いた形になる。

### 3.2 原因:物理的に無害な高さ差まで減点していた

奥の天面 T_b の上に後から着地する荷物は、底面が T_b + REST_CLEARANCE(0.016)を目標にし、直置き面でなければさらに START_Z(0.08)浮上した高さで掃引される。掃引時に要求される z 方向余裕は SWEEP_Z_MARGIN(0.0155)。したがって

```
CORRIDOR_DEADBAND = REST_CLEARANCE + START_Z − SWEEP_Z_MARGIN = 0.016 + 0.08 − 0.0155 = 0.0805 [m]
```

までの高さ差では**搬入経路はまだ生きている**。初版はこの範囲まで減点していたため、通路を全く塞いでいない候補どうしの順位まで揺さぶっていた。この定数は任意の調整パラメータではなく、`_evaluate_candidates` の掃引高さ計算式から一意に決まる値である。

### 5.3 判定と含意

**Y_SLICE 構造への介入は Phase9(固定4分割)・Phase13(到達高さで強制開放)・Phase14(棚シーンで分割無効化)の3連敗**となった。一方、本フェーズのターゲット1が示したとおり、**同じ「搬入経路を守る」という目的でも、探索構造ではなくスコアに載せると素直に効く**。この非対称性は今後の設計指針として明確である。

## 6. Phase15 への申し送り

1. **P02_A_1c_pre10 の −8.12/−13.04 を回収する(最優先)。** 本フェーズ唯一の大きなコスト。after で決定的に低い解へ収束しているので原因の特定は容易なはず。仮説は「積付済みシーンでは既積み層の最低天面を corridor_penalty が過剰に守り、その上への積み上げを抑制する」。既積み荷物(初期状態から存在する荷物)を `min_top_behind` の計算から除外する、あるいは既積み層に限って不感帯を広げる、といった限定的な修正で検証する価値がある。P01 が +8.41 と大きく改善している一方 P02 だけが落ちている点も、pre-packed 特有の条件が効いていることを示唆する。
2. **corridor_penalty の重み再調整は不要と考えられる。** 不感帯導入後は W∈{3,6,12} という広い台地があり、6.0 はその中央。P02 の件は重みではなく `min_top_behind` の定義側で解くべき。
3. **gen_shelf_patternA(fill 25.23、配置14個、fail_transport_y 62.3%)は依然として未解決。** 本フェーズの改善はこのシーンに1ビットも届いていない(エピソードが完全に同一)。ただし **Y_SLICE 構造をいじる方向は3連敗したので打ち切りを推奨**。次に試すなら、棚の下/上の空間を明示的に区別する候補生成(例: 棚上面を独立した「床」として扱い、棚下の低い空間には低い荷物だけを割り当てる)など、スコア側または候補生成側の変更が筋。
4. **26シーン×3回のノイズ床(fill_strict ±0.45 / fill_loose ±0.39)が実測できた**(§2)。今後の当落判定はこの値を基準に使える。パターンB 5シーンでの先行掃引 → 26シーン×3回で確定、という2段構えは本フェーズで有効に機能したので踏襲を推奨する。
